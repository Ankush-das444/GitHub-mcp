Your repos, exposed as tools a model can call.

A stateless remote MCP server on Vercel serverless. Point any MCP client at /api/mcp, pass a GitHub token per request, and the model can read issues and files — or commit one. No device stays on, nothing is self-hosted, no session is stored.

Connect a client in four steps

        
The server never stores your token — it arrives on each request, or sits in a Vercel env var if this deployment is only for you.

      


      

        

          
01
Make a GitHub token
fine-grained, scoped to the repos it should touch

          
GitHub → Settings → Developer settings → Personal access tokens. Contents: read/write only if you want push_file; Issues: read/write for create_issue. Read-only tokens still get all four read tools.

        


        

          
02
Deploy
or npm run serve for local

          

        


        

          
03
Check it answers
GET is a health check, POST speaks MCP

          

          

        


        

          
04
Add it to your client
just the URL — nothing to save

          

            A remote MCP server is a URL. In claude.ai go to
            Settings → Connectors → Add custom connector and paste it;
            Claude Desktop and Cursor have the same "add by URL" dialog. There is no settings file to write.
          

          

          

            If this deployment doesn't carry its own token, the same dialog has a field for one header:
            Authorization = Bearer <PAT>.
            Set GITHUB_TOKEN on Vercel and even that goes away — the URL alone is the whole setup.
